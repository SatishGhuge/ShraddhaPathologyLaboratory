TROUBLESHOOTING QUICK REFERENCE
================================================================================

Issue: "AISensy API Key not configured"
Fix: Add AISENSY_API_KEY to .env and restart server

Issue: Phone number invalid format error
Fix: Format phone as +91XXXXXXXXXX before sending
     System auto-formats: 10-digit → +91XXXXXXXXXX

Issue: "Payment not complete" when authorizing
Fix: This is correct behavior! Check balance:
     SELECT balanceAmount FROM visit_bills WHERE visitId = 'VIS001';
     Record full payment first, then authorize

Issue: Message not sent but no error
Fix: Check patient/doctor contact details:
     - For WhatsApp: patient.mobile or doctor.mobile required
     - For Email: patient.email or doctor.email required
     - Check reportMode or Doctor.sendReportsVia* flags

Issue: notification_logs table not found
Fix: Run database migration:
     npx prisma migrate dev

Issue: Doctor didn't receive message
Fix: Check doctor preferences:
     SELECT sendReportsViaWhatsApp, sendReportsViaMail, mobile, email 
     FROM doctors WHERE id = ?;
     Both flags might be false (opted out)

MONITORING DASHBOARD QUERIES
================================================================================

Copy these into your monitoring system:

-- Total sends today
SELECT COUNT(*) as total FROM notification_logs WHERE DATE(createdAt) = TODAY();

-- Success rate
SELECT 
  status,
  COUNT(*) as count,
  CONCAT(ROUND(COUNT(*)*100/SUM(COUNT(*)) OVER(), 2), '%') as percentage
FROM notification_logs
WHERE createdAt > DATE_SUB(NOW(), INTERVAL 24 HOUR)
GROUP BY status;

-- Failed reasons
SELECT errorMessage, COUNT(*) as count FROM notification_logs 
WHERE status = 'FAILED' 
AND createdAt > DATE_SUB(NOW(), INTERVAL 24 HOUR)
GROUP BY errorMessage
ORDER BY count DESC;

-- By template
SELECT eventType, COUNT(*) as sends, 
  SUM(CASE WHEN status = 'SUCCESS' THEN 1 ELSE 0 END) as success
FROM notification_logs
WHERE createdAt > DATE_SUB(NOW(), INTERVAL 24 HOUR)
GROUP BY eventType;
