QUICK START (5 MINUTES)
═══════════════════════════════════════════════════════════════════════════

1. INSTALL DEPENDENCIES
   npm install

2. CONFIGURE
   cp .env.example .env
   # Edit .env with your values (see CONFIGURATION below)

3. SETUP DATABASE
   mysql -u root -p
   > CREATE DATABASE lab_agent_db;
   > use lab_agent_db;
   > [paste TABLE SCHEMA from DEPLOYMENT_GUIDE.txt section 5]

4. START AGENT
   npm start

5. TEST WITH SIMULATOR
   # In a new terminal while agent is running:
   node simulator.js VIS001 SAM001 ALT^AST^CHOL

6. VERIFY DATABASE
   mysql -u root -p lab_agent_db
   > SELECT * FROM pending_results ORDER BY id DESC LIMIT 1 \G

═══════════════════════════════════════════════════════════════════════════
ASTM FRAME FLOW
═══════════════════════════════════════════════════════════════════════════

Erba EM 200 → Agent Flow:

1. HEADER (H)
   H|\\^&|||EM200||||||N||E1394-97|[timestamp]
   → ACK

2. QUERY (Q) - Analyzer scans barcode
   Q|1|[sampleId]|||[testCodes]||
   → ORDER frame sent back (agent → analyzer)
   → ACK

3. RESULT (R) - One frame per test
   R|1|^^^[testCode]|[value]|[units]|[refRange]|[flag]|||[status]|||
   → ACK (repeated for each result)

4. TERMINATOR (L)
   L|1|N
   → ACK, then process accumulated results

RESULT FLAGS
═══════════════════════════════════════════════════════════════════════════

N     Normal (within reference range)
H     High (above reference upper limit)
L     Low (below reference lower limit)
HH    Critically High

A     Abnormal

<     Below linear/technical range limit

═══════════════════════════════════════════════════════════════════════════
TROUBLESHOOTING QUICK FIXES
═══════════════════════════════════════════════════════════════════════════

Issue: "Port 5200 already in use"
→ Change TCP_PORT in .env or kill process: taskkill /PID [pid] /F

Issue: Database connection refused
→ Start MySQL: net start MySQL80
→ Check credentials in .env

Issue: VPS timeout
→ Check URL correct: curl http://192.168.0.119:5000/api/health
→ Check Tailscale connected

Issue: Results stuck as OFFLINE_QUEUED
→ Check VPS reachable
→ Check retry_count < 10 (max retries)
→ If >= 10, mark FAILED and investigate

Issue: No frames from analyzer
→ Check analyzer network configured (IP + port 5200)
→ Test connectivity: telnet [pc-ip] 5200
→ Check Windows firewall allows Node.js

Issue: "Cannot find module 'mysql2'"
→ npm install (reinstall dependencies)
→ rm -rf node_modules && npm install (clean install)


═══════════════════════════════════════════════════════════════════════════
MONITORING LOGS
═══════════════════════════════════════════════════════════════════════════

Live Log Output (Windows):
  • "[TCP] Connected: [IP]" = Analyzer connected
  • "[ASTM PARSER] Record type: R" = Result received
  • "[DB SUCCESS] Result stored: id=X" = Saved to DB
  • "[CLOUD] Result sent" = Synced to VPS (success)
  • "[SYNC] VPS not reachable" = Offline queued

Key Log Patterns:
  [TCP]              = Network/connection events
  [ASTM PARSER]      = Frame parsing
  [DB]               = Database operations
  [CLOUD]            = VPS sync
  [RETRY WORKER]     = Offline retry cycles
  [ERROR]            = Problems to investigate

PERFORMANCE STATS
═══════════════════════════════════════════════════════════════════════════

Query Database Statistics:

SELECT 
  status,
  COUNT(*) as count,
  AVG(retry_count) as avg_retries
FROM pending_results
GROUP BY status;

Expected Results (healthy system):
  SYNCED:            Most records (>95%)
  OFFLINE_QUEUED:    Few (<5%)
  FAILED:            None (or very few if network issues)
  PENDING:           None (should be processed immediately)

PRODUCTION DEPLOYMENT OPTIONS
═══════════════════════════════════════════════════════════════════════════

Option A: Direct Node.js (Development/Testing)
  npm start
  → Runs in foreground, shows all logs
  → Keep terminal open

Option B: Windows Service (Production)
  npm install -g nssm
  nssm install ErbaEM200Agent node app.js
  nssm start ErbaEM200Agent
  → Runs automatically at startup
  → Runs as Windows service
  → Check logs in configured log files

Option C: Linux Systemd (Production)
  sudo systemctl enable erba-em200-agent.service
  sudo systemctl start erba-em200-agent.service
  sudo journalctl -u erba-em200-agent.service -f
  → Runs automatically at startup
  → Integrated with system logging

Option D: Standalone Executable (No Node.js required)
  npm run build
  → Creates dist/erba-em200-agent.exe
  → Can copy to any Windows PC (no Node.js needed)
  → Run with arguments: erba-em200-agent.exe
